Enhancement Narrative

Artifact Description

The artifact I selected for the databases enhancement is the Grazioso Salvare Animal Shelter project that I originally developed in CS 340. The project uses Python and MongoDB to manage and retrieve animal shelter information for a rescue-oriented dashboard. Its Python data-access module provides create, read, update, and delete operations on animal records. I selected this artifact because it offered an opportunity to strengthen database access, data integrity, and the way information is retrieved and presented.

Justification and Enhancement

My original module established a MongoDB connection and supported basic CRUD operations. For the enhancement, I added validation for important animal fields, optional sorting, paginated results, and a dedicated search method that filters by animal type and breed. I also improved error reporting through Python logging and added a method to create indexes on commonly searched fields. These changes make the database access layer more deliberate and easier to extend.

I added safeguards to reject empty update and delete queries so that an accidental unrestricted operation cannot be performed through those methods. The enhanced update method also rejects changes to the immutable MongoDB _id field and invalid update-field names. The search and read methods provide structured ways to retrieve records, while pagination can reduce the number of results returned in a single request.

In MongoDB Compass, I created ascending indexes for animal_type and breed in the local aac_demo.animals collection. Explain Plan showed an IXSCAN using animal_type_1 for a query returning three dog records. A separate query showed an IXSCAN using breed_1, although the specific breed searched returned no matching records. These results demonstrate that MongoDB could select the indexes; they do not establish a measurable speed improvement on a four-record dataset.

Course Outcomes

This enhancement demonstrates the application of computing practices to improve an existing data-driven system. I considered how indexing, query filtering, and pagination affect the organization and retrieval of data, and I strengthened the code's validation and safeguards to support a security-minded approach to database operations. The work also reflects the use of appropriate development tools and technologies, including Python, PyMongo, MongoDB Compass, and Visual Studio Code.

Reflection

One challenge was reconnecting the original CS 340 project to a local MongoDB environment. I located the original Python files, preserved a separate copy, installed PyMongo, and adjusted the connection settings to match the local development server. I then tested the enhanced module using a small demonstration collection. This process reinforced the importance of verifying the environment and testing changes incrementally rather than assuming that working source code will run without configuration.

Testing also highlighted the difference between adding a feature and demonstrating that it works. I verified the connection, search results, sorted and paginated output, rejection of invalid records, and protection against an empty delete query. I learned that query plans provide stronger evidence of index usage than simply seeing an index listed in the database. The enhancement remains a standalone database module; the original dashboard has not yet been adapted or retested against its new default pagination behavior.

Test Results

The enhanced module was tested locally against aac_demo.animals, which contained four records. The following checks were observed:

  • MongoDB connection succeeded and returned four records.
  • Searching for animal_type='Dog' returned three records.
  • Sorting by animal type and requesting page 1 with a page size of 2 returned ['Cat', 'Dog'].
  • An attempted insertion with blank animal type and breed was rejected (False).
  • An empty delete query returned 0, and all four records remained.
  • MongoDB Explain Plan showed IXSCAN for both animal_type_1 and breed_1.

These are targeted functional checks, not a comprehensive automated test suite or a benchmark. Full dashboard integration and performance testing with a larger dataset are potential future improvements.
