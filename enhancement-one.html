Enhancement Narrative

The artifact I selected for the software design and engineering category is my CS 360 Weight Tracker Android application. I originally created this project in CS 360 as a mobile application that allows a user to create an account, log in, and keep track of daily weight entries. I selected it for my ePortfolio because it gave me a good opportunity to show more than just whether an application runs. It includes the user interface, data storage, account management, and several different activities that have to work together. For this enhancement, I worked on making the application more complete and more secure. I added stronger input validation, including checking that a date is not only in the correct format but is also an actual calendar date. I also improved the weight-entry functions so the user can add, view, edit, and delete entries. A confirmation message is shown before an entry is deleted, which helps prevent accidental data loss. I also added goal-weight settings and SMS alert options. One of the most important security improvements was changing the login process so that passwords are hashed instead of being stored as plain text in the database.

This enhancement helped me make progress toward several of the course outcomes I planned to address. It especially supports the outcome involving the use of computing techniques, skills, and tools to create solutions that provide value. The application now has better validation, improved CRUD functions, additional user features, and a more organized connection between the interface and the SQLite database. It also supports the security outcome because I had to think more carefully about how user information is stored and protected. Password hashing was an important improvement because the original version stored passwords in plain text. I also had to think about user mistakes, not just programming errors, which led to the date validation and delete confirmation. At this point I do not think I need to change my overall outcome-coverage plan, but this enhancement gave me more security-related evidence than I originally expected.

The process of enhancing the application also showed me how one change can affect other parts of a program. Some improvements worked right away, while others required troubleshooting. For example, when I added stronger date validation, Android Studio reported API-level compatibility errors because some of the date functions required a newer API than the project's minimum version. I had to adjust the implementation so the application would still support the project's API level. I also tested the application instead of assuming that the code changes worked. I created a new account, logged in, entered an invalid date to make sure it was rejected, added a valid weight entry, edited the entry, and then deleted it using the confirmation dialog. I also tested the goal-weight settings and enabled the SMS alert option. Working through these changes reminded me that improving software is not just about adding more code. It also involves testing, finding problems, making changes, and checking that existing features still work after the enhancement.
